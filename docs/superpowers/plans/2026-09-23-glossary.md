# 术语词典实施计划

**目标：** 在现有题库内新增独立词典和答案内释义，保持题目数据、学习记录及原有页面样式不变。

**结构：** 用户 JSON 原样包装为 `glossary-data.js`；纯匹配与搜索放入 `glossary-core.js`；词典页放入 `glossary.js`/`glossary.css`；答案文本注解及弹层独立放入 `glossary-highlighter.js`/CSS。

**技术：** 现有原生 JavaScript、CSS 主题变量、DOM TreeWalker、MutationObserver、Node test runner、Playwright CLI。

- [x] 原样导入 443 词条、15 分类，校验与用户文件深度一致及题库文件哈希不变。
- [x] 先测试搜索、分类、长词优先、英文边界、歧义排除和 Unicode 匹配，再实现纯匹配引擎。
- [x] 新增桌面导航和移动“更多”内入口，独立搜索及分类，仅显示名称和一句话解释；返回原页面恢复题库筛选、页码与滚动位置。
- [x] 仅注解 `.study-answer` 文本，排除代码、链接、按钮、输入框、可编辑区域及元信息；重复渲染不嵌套高亮，同一答案同一术语只注解一次。
- [x] 点击或键盘打开小型释义弹层，Escape/外部点击关闭；使用 textContent 写入词典内容，遵循现有主题，移动端避免越界。
- [x] 浏览器验证搜索、分类、翻页、收藏、掌握状态、答案展开、暗色模式、移动导航、弹层焦点与离线可用性。
- [x] 运行全量测试及 diff 检查，独立审查，更新离线缓存版本；按会话授权发布并核对线上资源。

词典入口使用独立模式标志。打开词典时保留原页面状态；返回原入口时不执行会清空筛选的初始化流程。匹配只改变 DOM，不改写题库及用户内容。单字和词典明确标为易歧义的词仅供搜索，不自动高亮。英文以保守大小写和标识符边界匹配，防止把 GET/get 或 AOP/AOPConfig 混为一谈。
